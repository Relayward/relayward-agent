# Relayward Agent

Relayward Agent is the native node-side component of Relayward. It maintains an outbound control connection, supervises runtime plugins, enforces local policy while the center is unavailable, and delivers durable telemetry.

The supported targets are Debian/systemd and Alpine/OpenRC on Linux AMD64. The Agent does not require Docker and does not embed Xray, sing-box, or any other proxy core.

The Agent currently supports one-time registration, an authenticated outbound WebSocket control session, persisted heartbeats, durable idempotent commands, an at-least-once event queue, and supervised self-update with automatic rollback. Plugin supervision and local policy enforcement are implemented in later first-release stages.

## Installation

Each GitHub Release contains one static Linux AMD64 binary and one installation archive for both supported init systems. A short-lived, single-use registration token generated by the center can be passed directly to the installer:

```bash
curl --proto '=https' --tlsv1.2 -fsSL \
  https://github.com/Relayward/relayward-agent/releases/latest/download/install.sh |
  sudo env RELAYWARD_REGISTRATION_TOKEN=rwr_example \
  sh -s -- --server-url https://relayward.example.com
```

The installer verifies `SHA256SUMS`, rejects unexpected archive entries, creates the restricted `relayward-agent` service account, and installs either the systemd or OpenRC service. Configuration is stored under `/etc/relayward-agent`; all mutable Agent state and immutable binary versions are stored under `/var/lib/relayward-agent`.

The stable launcher starts the binary selected by `/var/lib/relayward-agent/current`. An `agent.update` command downloads only from the official Relayward Agent GitHub repository, validates the release manifest, binary size, SHA-256, runtime assets, and reported version, then requests a supervised restart. The candidate is confirmed only after an authenticated heartbeat acknowledgement. Startup or health failure before confirmation restores the previous immutable version.

## Registration And Control

Create the local configuration before enrollment:

```bash
relayward-agent init-config \
  --server-url https://relayward.example.com \
  --state-directory /var/lib/relayward-agent
```

The optional `--server-cert-sha256` value adds a leaf-certificate pin while retaining normal TLS verification. Plain HTTP is rejected unless `--allow-insecure` is explicitly set for local tests.

Use the short-lived token generated by the center exactly once:

```bash
RELAYWARD_REGISTRATION_TOKEN=rwr_example relayward-agent enroll
relayward-agent run
```

The identity is stored at `/var/lib/relayward-agent/identity.json` with mode `0600`. The registration token and node credential are never printed by these commands.

Accepted commands and terminal results are stored as owner-only JSON files under `/var/lib/relayward-agent/commands`. Heartbeats continue while commands execute. A terminal result remains on disk and is resent after reconnect until the center acknowledges it; acknowledged records are retained for 24 hours to prevent duplicate execution.

Events are stored in the owner-only `/var/lib/relayward-agent/events.db` queue with 64 MiB and 100,000-event default limits. The Agent uploads independent gzip batches over HTTPS and removes only the highest contiguous range acknowledged by the center.

## Local Checks

```bash
go test ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./cmd/relayward-agent
```

Print build information:

```bash
go run ./cmd/relayward-agent version
```

Releases use semantic `vMAJOR.MINOR.PATCH` Git tags and publish only Linux AMD64 assets. GitHub is the release trust root; manifests contain SHA-256 metadata but are not separately signed.
